# ペーパートレードが対照実験になるのは、本番の注文と同じ経路を通るときだけ

_ペーパーでの試運転は、取引ルールが実際の資金で何をしたかを示すためのものです。それができるのは、シグナル、注文、タイミング、コストが同じ経路を通るときだけです。そうでないと何が崩れるのかをまとめます。_

ある取引ルールがバックテストを通りました。資金を入れる前に、数週間ペーパーで動かします。ペーパーの結果がバックテストと似ていれば、そのルールを本番に移します。慎重なトレーダーの多くがとる手順で、良い手順です。ただし、気づかないうちに崩れやすい前提が一つあります。ペーパーの試運転が、本番と同じことをしているという前提です。

実験の言葉でいえば、ペーパートレードは対照です。対照が役に立つのは、本物との違いがちょうど一つだけのときです。ここでの違いは「お金が動かない」ことだけであるべきです。価格が届いてから約定が記録されるまでの、それ以外のすべては同じであるべきです。

## ペーパーと本番がずれていくところ

ペーパーの仕組みは、本番のシステムとは別に、しかも急いで作られることがよくあります。小さな違いが積み重なります。

**シグナルの計算が違う。** バックテストのコードをペーパーに流用し、本番には速さ重視の別のコードがある。一方は値を丸め、もう一方は丸めない。一方は足の終値を使い、もう一方は数秒前の最後の約定を使う。たいていの日は誰も気づきません。肝心な日に、二つの答えが食い違います。

**タイミングが違う。** ペーパーでは確定した足で判断し、その足の価格で約定させることがよくあります。本番では、足が確定するのを見て、計算し、注文を出し、待ちます。得られるのは数秒後、数分後の価格です。短い値動きを狙うルールは、その隙間で優位のほとんどを失うことがあり、ペーパーはそれを決して見せません。

**約定が想像上のもの。** ペーパーでは、どの注文も全量、希望した価格で約定したことにするのが普通です。本番の注文は一部だけ、遅れて、あるいはまったく約定しないことがあり、取り逃がした注文ほど、実は一番良い結果になるはずだったものだったりします。

**コストが抜けているか、当て推量。** 手数料、スプレッド、ポジションを翌日に持ち越すコストは、簡単に抜け落ちます。あるいは一度だけきりのいい数字で入れて、二度と見直されません。

**障害が起きない。** ペーパーでは、注文の拒否も、接続の切断も、取引の途中での再起動もありません。本番では起きます。そのたびにシステムがどう振る舞うかも、ルールが実際の資金で行うことの一部です。別の経路で作ったペーパーは、そこを決して試しません。

一つ一つは小さなことです。合わせると、ペーパーは本番に出すものとは少し違うルールを測っていることになります。そして後で二つが食い違ったとき、変わったのがルールなのか、配管だけなのか、誰にもわかりません。

## ペーパーを正直な対照にするには

直し方は一言で言えます。ペーパーと本番を一つの経路に通すことです。同じコードがシグナルを計算し、同じコードが注文を組み立て、同じ時計がいつ出すかを決め、同じコストのモデルを当てはめます。最後の一歩だけ、片方は注文を模擬の帳簿へ、もう片方は取引所へ送ります。その最後の一歩が唯一の違いなので、ペーパーと本番の差の原因として疑えるのもそこだけになります。

そこから、いくつかの確認が出てきます。

- ペーパーが何を、いつ、いくらで決めたかを、本番が記録するのと同じ形で残す。そうすれば合計だけでなく、一行ずつ比べられます。
- コストは初日から、払うと見込む水準で入れ、実際の約定が出てきたら見直す。
- ペーパーを本番より甘くしない。本番が足の確定を待ってから注文を出すなら、ペーパーも同じように待ち、同じように値を付ける。
- バックテストより良く見えるペーパーは、良い知らせではなく警告として扱う。たいていは、経路のどこかが簡単すぎるという意味です。

どれも、そのルールが良いという意味ではありません。悪いルールを忠実にペーパーで動かしても、悪いルールのままです。得られるのは信頼できる読み取りです。ペーパーと本番が同じ経路なら、二つの違いは市場の違いであって、ソフトウェアの違いではありません。
